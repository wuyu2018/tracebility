# 登录失败次数限制修复说明

## 问题描述

### 风险等级
🔴 **严重** - 管理员账号安全

### 影响范围
- 管理员登录接口 `/api/login`
- 所有管理员账号

### 安全问题

当前实现存在严重的安全缺陷：
1. **无失败次数限制**：攻击者可以无限次尝试密码组合
2. **无账号锁定机制**：即使多次失败也不会锁定账号
3. **验证码机制缺陷**：验证码存储在内存，可通过同一 IP 不断请求新验证码
4. **暴力破解风险**：攻击者可以使用字典攻击尝试常见密码

### 攻击场景

```
攻击者流程：
1. 获取目标管理员账号（admin）
2. 使用自动化工具不断尝试密码
3. 每次失败后请求新验证码
4. 继续尝试下一个密码
5. 最终可能破解弱密码账号
```

## 修复方案

### 设计思路

实现基于 Redis 的登录失败计数和账号锁定机制：
- 使用 Redis 存储失败次数（1 小时过期）
- 5 次失败后自动锁定账号 30 分钟
- 登录成功自动清除失败记录
- 验证码错误也计入失败次数（防止绕过）

### 技术实现

#### 1. LoginAttemptService（登录尝试管理服务）

**核心参数**：
- `MAX_ATTEMPTS = 5`：最大失败尝试次数
- `LOCK_TIME_MS = 30 * 60 * 1000`：账号锁定时间（30 分钟）

**主要方法**：

```java
// 记录登录失败
public void loginFailed(String username)

// 检查账号是否被锁定
public boolean isLocked(String username)

// 获取剩余锁定时间（秒）
public long getRemainingLockTime(String username)

// 登录成功，清除失败记录
public void loginSucceeded(String username)

// 手动解锁账号（管理员使用）
public void forceUnlock(String username)
```

**Redis Key 设计**：
- `login_failed:{username}`：存储失败次数（Integer）
- `locked:{username}`：存储锁定时间戳（Long）

#### 2. RedisConfig（Redis 配置）

配置专用的 RedisTemplate：
```java
@Bean
public RedisTemplate<String, Integer> failedAttemptsTemplate()

@Bean
public RedisTemplate<String, Long> lockedAccountsTemplate()
```

#### 3. AdminServiceImpl（登录逻辑）

**登录流程**：
```
1. 检查账号是否被锁定
   ↓ 已锁定 → 返回错误（剩余时间）
2. 验证验证码
   ↓ 错误 → loginFailed() → 返回错误
3. 验证账号密码
   ↓ 错误 → loginFailed() → 返回错误
4. 登录成功
   ↓ loginSucceeded() → 生成 JWT Token
```

**关键代码**：
```java
public LoginResponseDTO login(AdminLoginDTO loginDTO) {
    String username = loginDTO.getUsername();
    
    // 检查账号是否被锁定
    if (loginAttemptService.isLocked(username)) {
        long remainingSeconds = loginAttemptService.getRemainingLockTime(username);
        throw new BusinessException(String.format(
            "账号已被锁定，请 %d 分钟后再试", 
            remainingSeconds / 60 + 1
        ));
    }
    
    // 验证码验证（错误也计数）
    if (!captchaStorage.isValid(username, captcha)) {
        loginAttemptService.loginFailed(username);
        throw new BusinessException("验证码错误");
    }
    
    // 密码验证
    if (!passwordEncoder.matches(password, admin.getPassword())) {
        loginAttemptService.loginFailed(username);
        throw new BusinessException("账号或密码错误");
    }
    
    // 登录成功，清除记录
    loginAttemptService.loginSucceeded(username);
    // ...
}
```

## 工作流程

### 场景 1：正常登录
```
用户登录 → 验证成功 → 清除失败记录 → 生成 Token
```

### 场景 2：密码错误（未达上限）
```
用户登录 → 密码错误 → 失败次数 +1 → 返回"账号或密码错误"
剩余尝试次数：5 - 当前失败次数
```

### 场景 3：账号锁定
```
第 5 次失败 → 达到 MAX_ATTEMPTS → 自动锁定账号
↓
存储锁定时间戳到 Redis
返回："账号已被锁定，请 30 分钟后再试"
↓
30 分钟内所有登录请求直接拒绝
显示剩余锁定时间（分钟）
↓
30 分钟后自动解锁，清除锁定状态
```

### 场景 4：验证码错误绕过尝试
```
攻击者尝试：
1. 故意输错验证码
2. 期望不计入失败次数
3. 实际：loginFailed() 仍会调用
4. 5 次后账号同样被锁定
```

## 安全增强效果

### 防护能力提升

| 攻击类型 | 修复前 | 修复后 |
|---------|--------|--------|
| 暴力破解 | ❌ 无限制 | ✅ 5 次后锁定 |
| 字典攻击 | ❌ 可无限尝试 | ✅ 30 分钟冷却 |
| 验证码绕过 | ❌ 可故意输错 | ✅ 同样计数锁定 |
| 自动化攻击 | ❌ 无阻碍 | ✅ 被锁定阻止 |

### 时间成本计算

**攻击者破解 6 位密码（假设）**：
- 密码空间：10^6 = 1,000,000 种组合
- 修复前：可无限尝试，理论上必中
- 修复后：
  - 每 5 次失败需要等待 30 分钟
  - 尝试 1,000,000 次需要：1,000,000 / 5 × 30 分钟 = 6,000,000 分钟 ≈ 11.4 年

**结论**：暴力破解在时间上不再可行

## 配置参数

### 可调整参数

```java
// LoginAttemptService.java
private static final int MAX_ATTEMPTS = 5;           // 最大失败次数
private static final long LOCK_TIME_MS = 30 * 60 * 1000; // 锁定时间 30 分钟

// Redis 过期时间
failedAttemptsTemplate.expire(key, 1, TimeUnit.HOURS); // 失败记录 1 小时过期
```

### 建议配置

| 参数 | 当前值 | 建议范围 | 说明 |
|------|--------|---------|------|
| MAX_ATTEMPTS | 5 | 3-10 | 平衡安全和用户体验 |
| LOCK_TIME_MS | 30 分钟 | 15-60 分钟 | 根据安全需求调整 |
| 失败记录过期 | 1 小时 | 30 分钟 -24 小时 | 自动清理过期数据 |

## 运维说明

- `login_failed:*` Key 的数量：监控攻击频率
- `locked:*` Key 的数量：监控被锁定账号数

### 紧急解锁

管理员账号被误锁定，可以手动解锁：

**方法 1：Redis CLI**
```bash
# 查看锁定状态
redis-cli GET "locked:admin"

# 手动删除锁定
redis-cli DEL "locked:admin"
redis-cli DEL "login_failed:admin"
```

## 测试验证

### 测试用例

**用例 1：正常登录**
```
1. 输入正确账号密码
2. 验证通过，返回 Token
3. Redis 中无失败记录
```

**用例 2：密码错误 3 次**
```
1. 第 1 次错误：返回"账号或密码错误"，失败计数=1
2. 第 2 次错误：返回"账号或密码错误"，失败计数=2
3. 第 3 次错误：返回"账号或密码错误"，失败计数=3
4. 检查 Redis：login_failed:admin = 3
```

**用例 3：账号锁定**
```
1-4. 连续错误 4 次
5. 第 5 次错误：返回"账号已被锁定，请 30 分钟后再试"
6. 检查 Redis：locked:admin = 时间戳
7. 尝试登录：直接返回锁定错误
8. 前端显示：黄色警告框 + 剩余时间
```

**用例 4：自动解锁**
```
1. 等待 30 分钟 + 1 秒
2. 尝试登录：允许尝试
3. 如果密码正确：登录成功，清除记录
4. 如果密码错误：重新计数
```

**用例 5：验证码错误**
```
1. 输入错误验证码
2. 返回"验证码错误"
3. 检查 Redis：失败计数 +1
4. 达到 5 次后同样锁定账号
```
