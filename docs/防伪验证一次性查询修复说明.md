# 防伪验证"一次性查询"功能修复说明

## 问题描述

### 风险等级
🔴 **严重** - 核心业务逻辑缺陷

### 问题
防伪验证功能未能正确实现"一次性验证"机制：
- 首次验证成功后，同一防伪码再次查询仍返回 `valid: true`
- 无法区分首次查询和重复查询
- 伪造的防伪码如果是首次扫描也会显示为"真品"
- 防伪系统形同虚设

### 根本原因
1. `Product` 实体中不存在 README 描述的 `lastQueriedTime` 字段
2. 代码仅记录 `SecurityCode.scanCount`（查询次数），但不根据次数返回 `valid:false`
3. `buildTraceInfoDTO` 方法设置了 `isQueried` 和 `queryTip`，但 Controller 仍然返回 `valid:true`

## 修复方案

### 设计思路
基于 `SecurityCode.scanCount` 字段判断查询次数：
- `scanCount = 0` 或 `null`：未查询过
- `scanCount = 1`：首次查询，返回 `valid: true`
- `scanCount > 1`：重复查询，返回 `valid: false`，提示伪品警示

### 后端修改

#### 1. TraceabilityServiceImpl.java

**修改 `getTraceInfoByCode` 方法**：
```java
// 判断是否为首次查询
boolean isFirstQuery = securityCode.getScanCount() == null || securityCode.getScanCount() == 0;

if ("未激活".equals(securityCode.getStatus())) {
    securityCode.setStatus("已激活");
    securityCode.setFirstScanTime(LocalDateTime.now());
    securityCode.setScanCount(1);
} else {
    // 重复查询，scanCount + 1
    securityCode.setScanCount(securityCode.getScanCount() + 1);
}
securityCodeRepository.save(securityCode);

return Optional.of(buildTraceInfoDTO(product, batch, securityCode, false));
```

**修改 `buildTraceInfoDTO` 方法**：
```java
if (securityCode.getScanCount() != null && securityCode.getScanCount() > 1) {
    dto.setIsQueried(true);
    dto.setQueryTip("该产品已被查询过 " + (securityCode.getScanCount() - 1) + 
                   " 次，首次查询时间：" + securityCode.getFirstScanTime() + 
                   "。重复查询可能是伪品，请谨慎购买！");
} else {
    dto.setIsQueried(false);
    dto.setQueryTip(null);
}
```

#### 2. TraceabilityController.java

**修改 `/api/verify` 接口**：
```java
if (result.isPresent()) {
    TraceInfoDTO traceInfo = result.get();
    
    // 检查是否为重复查询
    if (traceInfo.getIsQueried() != null && traceInfo.getIsQueried()) {
        log.warn("[防伪验证] 重复查询 - 防伪码：{}, 已被查询 {} 次", 
                maskCode(code), traceInfo.getScanCount());
        return ResponseEntity.ok(Map.of(
            "valid", false,
            "message", "该产品已被查询过 " + (traceInfo.getScanCount() - 1) + 
                      " 次，首次查询时间：" + traceInfo.getFirstScanTime() + 
                      "，该产品可能是伪品，请谨慎购买！"
        ));
    }
    
    return ResponseEntity.ok(Map.of("valid", true, "data", traceInfo));
}
```

### 前端修改

#### 1. api.js
补充缺失的函数声明：
```javascript
export async function verifyAntiFakeCodeGet(code) {
  const { data } = await api.get('/verify', { params: { code } })
  return data
}
```

#### 2. VerifyForm.vue
正确处理 `valid=false` 的情况：
```javascript
async function queryByCode(code) {
  loading.value = true
  try {
    const result = await verifyAntiFakeCodeGet(code)
    if (result.valid && result.data) {
      emit('verified', result.data)
    } else {
      // valid=false 表示重复查询或无效码
      const message = result.message || '该产品可能是伪品，请谨慎购买！'
      emit('invalid', message)
    }
  } catch (err) {
    emit('invalid', '验证失败，请检查网络连接')
  } finally {
    loading.value = false
  }
}
```

#### 3. ResultDisplay.vue
添加重复查询警告横幅：
```vue
<!-- 重复查询警告 -->
<div v-if="traceData.isQueried" class="warning-banner">
  <span class="warning-icon">⚠️</span>
  <div class="warning-content">
    <h3>该产品可能已被查询过</h3>
    <p>{{ traceData.queryTip }}</p>
    <p class="warning-tip">请谨慎购买，如有疑问请联系正规渠道核实</p>
  </div>
</div>

<!-- 状态徽章 -->
<span class="warning-badge" v-if="traceData.isQueried">⚠️ 重复查询</span>
<span class="success-badge" v-else-if="traceData.status === '已激活'">✓ 正品验证通过</span>
```

## 验证流程

### 测试场景 1：首次查询（正品）
1. 扫描防伪码，访问 `/api/verify?code=XXX`
2. 后端：`scanCount` 从 0 → 1，设置 `status="已激活"`
3. 返回：`{ "valid": true, "data": {...} }`
4. 前端：显示"✓ 正品验证通过"，展示溯源信息

### 测试场景 2：重复查询（伪品警示）
1. 再次扫描同一防伪码
2. 后端：`scanCount` 从 1 → 2，`isQueried=true`
3. Controller 检查到 `isQueried=true`，返回：
   ```json
   {
     "valid": false,
     "message": "该产品已被查询过 1 次，首次查询时间：2026-01-15T10:30:00，该产品可能是伪品，请谨慎购买！"
   }
   ```
4. 前端：触发 `@invalid` 事件，显示伪品警告横幅

### 测试场景 3：无效防伪码
1. 扫描不存在的防伪码
2. 后端：`securityCodeOpt.isEmpty()` 为 true
3. 返回：`{ "valid": false, "message": "未找到该防伪码对应的产品信息..." }`
4. 前端：显示伪品警告

- ✅ 伪品警示：明确的警告提示

## 注意事项

### 数据库迁移
当前方案不需要修改数据库表结构，使用现有的 `SecurityCode` 实体字段：
- `scan_count`：查询次数
- `first_scan_time`：首次查询时间
- `status`：激活状态

### 兼容性
- 现有已生成的防伪码无需重新生成
- 历史数据（scanCount=0 或 null）会被视为首次查询
- 新逻辑对所有查询立即生效

### 性能影响
- 每次查询需要更新 `scan_count` 字段（+1）
- 增加了 `is_queried` 字段判断逻辑
- 对整体性能影响可忽略不计

## 后续优化建议

1. **IP 限流**：同一 IP 短时间内多次查询触发风控
2. **地理位置标记**：记录每次查询的地理位置
3. **异常告警**：短时间内同一防伪码在不同地区被查询，触发告警
4. **二维码加密**：防伪码采用更复杂的加密算法，防止伪造
5. **区块链存证**：将查询记录上链，确保不可篡改
