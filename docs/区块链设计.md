# 区块链防篡改设计

## 概述

本项目采用**类区块链数据结构**实现业务数据的防篡改审计日志，非传统区块链网络（无共识/P2P/矿工）。核心思路：hash 链 + RSA 签名保证数据一旦写入不可篡改。

---

## 双链架构

两条独立的链：

### 1. MATERIAL 链（全局单链）

- 记录所有 `material` 和 `material_purchase` 的创建/变更/删除
- 所有原料相关实体共享一条链，区块按时间顺序前后链接
- 不分 batch，全局唯一链  

### 2. BATCH 链（每条批次独立子链）

- 每条 `production_batch` 拥有一条独立链
- 记录该批次全生命周期：生产 → 入库 → 检验 → 运输销售
- 通过 `ref_master_chain_hash` 字段引用 MATERIAL 链最新 hash，实现交叉关联

---

## 区块结构

表名：`blockchain_log`

| 字段 | 说明 |
|---|---|
| `id` | 自增主键 |
| `chain_type` | 链类型：`MATERIAL` / `BATCH` |
| `batch_id` | 所属批次 ID（仅 BATCH 链使用） |
| `entity_type` | 实体类型（`MATERIAL` / `MATERIAL_PURCHASE` / `PRODUCTION_BATCH` / `STORAGE` / `INSPECTION` / `TRANSPORT_SALE`） |
| `entity_id` | 实体 ID |
| `action` | 操作类型（`CREATE` / `UPDATE` / `DEACTIVATE` 等） |
| `previous_hash` | 前一个区块的 `current_hash`，形成链式结构 |
| `current_hash` | 当前区块哈希 |
| `data_snapshot` | 操作时的数据快照（JSON） |
| `signature` | RSA 签名 |
| `timestamp` | 区块时间戳 |
| `operator_id` | 操作人 ID |
| `ref_master_chain_hash` | 引用的 MATERIAL 链最新 hash（仅 BATCH 链） |

## 密码学细节

### 哈希算法

```
current_hash = SHA-256(
    entityType + "|" +
    entityId + "|" +
    action + "|" +
    previousHash + "|" +
    dataSnapshot + "|" +
    timestamp
)
```

### 签名算法

- RSA-2048 密钥对
- SHA256withRSA 签名
- 对每个区块的 `current_hash` 进行签名
- 公钥可通过 API `/api/blockchain/public-key` 获取，用于外部验证

### 密钥管理

- 支持从 PEM 文件加载（配置项：`blockchain.rsa.private-key-path` / `public-key-path`）
- 文件不存在则启动时自动生成临时密钥对

## 写入流程（事件驱动）

```
领域事件 → @TransactionalEventListener → BlockchainService.appendBlock()
```

| 领域事件 | 触发时机 | 链 | 实体类型 |
|---|---|---|---|
| `BatchCreated` | 批次创建 | BATCH | PRODUCTION_BATCH |
| `GoodsReceived` | 入库完成 | BATCH | STORAGE |
| `InspectionCompleted` | 检验完成 | BATCH | INSPECTION |
| `TransportSaleRecorded` | 运输/销售记录 | BATCH | TRANSPORT_SALE |
| `MaterialChanged` | 原料变更 | MATERIAL | MATERIAL |
| `MaterialPurchaseChanged` | 采购变更 | MATERIAL | MATERIAL_PURCHASE |

所有事件监听器与业务事务绑定（同一事务），业务提交则区块链写入提交。

## 验证 API

| 端点 | 功能 |
|---|---|
| `GET /api/blockchain/verify/material` | 验证 MATERIAL 链完整性 |
| `GET /api/blockchain/verify/batch?batchId=X` | 验证指定 BATCH 链 |
| `GET /api/blockchain/verify/all` | 验证所有 BATCH 链 |
| `GET /api/blockchain/public-key` | 获取 RSA 公钥 |

### 验证规则

对链中每个区块依次检查：

1. **链式完整性**：第 i 块的 `previous_hash` 必须等于第 i-1 块的 `current_hash`
2. **哈希一致性**：用相同算法重算 `current_hash`，必须与存储值一致
3. **签名有效性**：用公钥验证 `current_hash` 的 RSA 签名

## 日终锚定

每天凌晨 3:00 定时任务 `BlockchainAnchorService.dailyAnchor()`：

1. 取 MATERIAL 链最新 hash → 写入 `blockchain_anchor` 表
2. 每条 BATCH 链最新 hash → 写入 `blockchain_anchor` 表
3. 写入文件 `logs/blockchain-anchor-YYYY-MM-DD.log`，每行附带 RSA 签名

该机制提供链状态的外部快照，即使 DB 被篡改，锚定日志可作为证据。

---

## 初始化

`BlockchainInitializationService`（`CommandLineRunner`）:

- 首次启动检测 DB 中是否已有区块链数据
- 若无，遍历所有历史业务数据，重建完整的 MATERIAL 链和 BATCH 链
- 幂等：已有数据则跳过
